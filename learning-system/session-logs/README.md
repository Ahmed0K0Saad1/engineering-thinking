# Session Logs

This directory is the permanent home for completed, meaningful session records.

## File Naming
Use:

`YYYY-MM-DD-unit-<unit-id>-<short-topic-slug>.md`

Example: `2026-11-18-unit-0.0-baseline-protocol-setup.md`

Use `templates/session-log.md` as the starting template. Do not overwrite earlier logs; create a new file for each meaningful session. Keep large artifacts in their appropriate project/evidence locations and link them from the log.

## Relationship to 09-current-status.md
- A session log is the detailed historical record: objective, work, learner evidence, assistance, errors, validation, and proposed mastery assessment.
- `09-current-status.md` is the concise current snapshot: active phase/unit, workflow status, next authorized action, current priorities, and links to the latest relevant logs/evidence.
- The status file is not a duplicate session diary. Update it only when the current execution state or an approved summary changes.
- Every mastery/status change in `09-current-status.md` must link to the supporting session log and/or evidence artifact.
- A log does not automatically change current status. Propose the update; apply it after the assessment is accepted or the evidence clearly supports it under the repository rules.
- Historical logs remain unchanged. Correct mistakes with a follow-up log and a status correction, preserving the audit trail.

## Minimum Record
A completed log must distinguish independent learner work from AI-assisted work and state what remains unverified. Never record a test that was not actually administered or a result that was not observed.
