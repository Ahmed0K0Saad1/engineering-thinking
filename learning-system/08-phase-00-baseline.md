# Phase 0 — Baseline & Learning Setup

**Workflow status:** NOT STARTED  
**Purpose:** Determine the real starting point without assuming zero knowledge or mastery.

## Phase 0 Scope
Audit mathematics, computing/CS, programming/problem solving, geospatial science, and selected existing-project understanding. Establish the repository records and AI workflow. Do not start AI/ML courses, a large new portfolio project, or a permanent specialization decision.

## Baseline Method
For each diagnostic topic, gather four forms of evidence:
1. Explain in the learner's own words.
2. Apply to a representative task.
3. Diagnose an error.
4. Transfer to a different context.

Use short, focused diagnostics. Avoid a large mixed exam. Record whether work was independent, AI-assisted, or directly guided.

## Pre-Diagnostic Protocol — Unit 0.0
No Phase 0 diagnostic may begin until Unit 0.0 is complete and the learner has approved the protocol. Unit 0.0 is setup, not a skills test.

Required readiness:
- Baseline matrix exists and includes project capability review.
- `learning-system/session-logs/` and its README exist.
- Session-log template and naming convention are clear.
- The distinction between workflow status and mastery state is understood.
- Session logs and `09-current-status.md` have defined separate responsibilities.
- First diagnostic topic is recorded in current status.
- Unit 0.0 readiness checklist is verified and logged.
- Learner explicitly approves starting the first diagnostic.

## First Diagnostic Topic
**Problem Understanding & Analytical Thinking** is the first topic to be diagnosed after Unit 0.0 passes its exit gate and the learner approves. Selecting the topic does not mean the diagnostic has started. Do not present questions, exercises, hints, or test scenarios before the protocol is complete and approved.

## Mathematics Audit
Topics: arithmetic, negative numbers, fractions, decimals, percentages, ratios, units/conversions, algebra, formula rearrangement, equations, geometry, angles, area/volume, trigonometry, coordinate geometry/distance, introductory vectors/matrices, descriptive statistics/probability, calculus exposure.

Evidence: independent calculations; formula rearrangement; geometry/trig task; coordinate task after prerequisites; unit/error explanation.

## Computing Audit
Topics: CPU/memory/storage/files; OS/process/environment/command line; binary/data representation; logic/algorithm tracing; collections/data structures; search/sort/complexity; networking/DNS/HTTP/client-server.

Evidence: explain a simple program's execution; trace an algorithm; explain paths/environments; compare search methods; explain a basic HTTP request/response.

## Programming Audit
Topics: Python syntax/types; conditions/loops/state; functions; collections; filtering/counting/aggregation/sorting; files; exceptions/debugging; modules/environments; OOP; tests; Git; independent problem solving.

Evidence: explain/modify a short program; solve one small problem without a template; debug a flawed example; write a test/check; disclose AI assistance.

## Geospatial Audit
Topics: surveying, observations, units, field notes; accuracy/precision/error/uncertainty; Earth models/geodesy/datums/reference frames; geographic/projected coordinates; projections; vector/raster/attributes/metadata/topology; GIS operations/cartography; remote sensing principles/resolutions; data quality.

Evidence: explain CRS/datum/projection distinctions; identify units/axis-order risks; interpret a small spatial dataset; explain why software success does not guarantee scientific validity; reason about measurement error.

## Existing Project Audit
For each selected project, use the project section in `templates/baseline-matrix.md`. Assess separately:
- independent execution and AI-assisted execution;
- explanation of architecture, design decisions, and limitations;
- ability to trace a feature end-to-end;
- independent modification, debugging, and testing;
- accurate disclosure of AI contribution.

Repository existence or successful AI-generated output does not prove independent mastery. Explanation and modification are separate capabilities and must have their own evidence.

## Baseline Matrix
Use `templates/baseline-matrix.md`. For every topic record evidence, result, assistance, misconception, mastery state, and next action: Skip for now / Review briefly / Study / Defer / Needs external or supervised practice. "Skip for now" is not permanent mastery.

## Environment Setup
Confirm repository access/local clone; read AGENTS.md; configure safe Git workflow; verify the records and log path; decide artifact locations; maintain one status file; avoid tools without a current purpose.

## Exit Gate
Mathematics, computing, programming, and geospatial baselines recorded; project understanding honestly assessed; priority gaps visible; first execution block selected from evidence; and the learner understands logging and AI workflow.

## First Authorized Action
Complete Unit 0.0 setup and its readiness checklist. Only after its exit gate and explicit learner approval may the first short diagnostic begin. Do not start a large new course before establishing the current level.
